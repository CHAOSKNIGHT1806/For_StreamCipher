====================================================================
新设计序列密码算法 —— 完整安全性分析提示词（整段复制粘贴给 agent）
====================================================================

请对一个**新设计的序列密码（流密码）算法**执行完整的、论文级的安全性分析，
使用工作区下已安装好的「序列密码安全性分析工具」（stream-cipher-analyzer），
最终产出可直接投稿的英文分析报告（默认 IEEE TIFS 结构）。

【输入】用户会提供该算法的 MATLAB 源代码（.m 文件）或伪代码。
       若尚未提供，先向用户索取，再开始。

【总原则】
- 每阶段产出可写进论文的中间结果，全部落到 <TOOL_DIR>\results\。
- 图用 PDF+PNG、表用 LaTeX+CSV。
- 诚实原则：NIST SP800-22 已于 2022-11 被 NIST 撤回（报告须注明）；可证明安全只给
  脚手架不伪造定理；FPGA 数据是定频估算模型。
- 关键输入（seed、位序 MSB/LSB、缩减轮范围、是否上云）在跑之前与用户确认。

--------------------------------------------------------------------
阶段 0：算法接入 + 翻译交叉验证（最关键，不通过不进后续阶段）
--------------------------------------------------------------------
1. 通读 MATLAB 源码，向用户确认并记录：
   - 更新规则/邻域半径/边界条件（周期/固定0/反射）
   - 状态位宽（胞元数/寄存器数）
   - 密钥与 IV 各多少位、如何注入（初始化轮数、混合方式）
   - 密钥流抽取方式（抽哪个胞元/哪些位、是否组合器、每轮出几位）
   - 预热丢弃轮数
2. 逐运算翻译为等价 Python/numpy（**保持算法与运算过程不变**：1-based→0-based 索引、
   位运算、mod 负数语义、循环先原样保留），封装成 CipherAdapter（继承
   analyzer.ingest.CipherAdapter，实现 keystream(key,iv,nbits)，可选 init/step/output_function）。
3. 【强制】向用户索要「同一 seed 下前若干胞元/bit 的密钥流」，与翻译版输出**逐 bit 比对**，
   完全一致才算翻译通过；不一致则排查翻译，直到一致再继续。

--------------------------------------------------------------------
阶段 1：黑盒随机性测试
--------------------------------------------------------------------
4. NIST SP 800-22（15 项 + 多序列 battery）：
   python cli.py analyze <适配器路径>:<类名> --nseq 100 --nbits 1000000
   （nseq=100 才够显著；报告注明标准已撤回）
5. TESTU01（金标准，按数据量由小到大）：
   python cli.py testu01 <适配器路径>:<类名> --battery smallcrush   # ~320 Mbit
   python cli.py testu01 <适配器路径>:<类名> --battery crush        # ~34 Gbit
   python cli.py testu01 <适配器路径>:<类名> --battery bigcrush     # ~274 Gbit，询问是否上云
   （TestU01 需 WSL；沙箱下运行 WSL 命令要提权 sandbox_permissions）

--------------------------------------------------------------------
阶段 2：线性与统计
--------------------------------------------------------------------
6. 记录 Berlekamp-Massey 线性复杂度（随机序列应 ≈ n/2）、monobit z、自相关、χ²、游程，
   全部进报告。

--------------------------------------------------------------------
阶段 3：结构攻击（按算法结构选用）
--------------------------------------------------------------------
7. 若是元胞自动机：先跑线性退化筛查（线性规则 LC 极低 → 直接判不安全）
   python cli.py ca-screen --rules <规则号>
8. 代数攻击：对小规模/缩减实例用 analyzer/algebraic.py（XL 线性化 + z3 SAT）实际求解
   初始状态；对完整规模报告"求解复杂度 vs 规模"曲线。
9. 立方体攻击：analyzer/cube.py 对低代数次数密码搜索 maxterm cube、恢复超多项式。
10. 相关攻击：analyzer/correlation.py 算最佳线性逼近（Walsh 谱）、相关免疫阶、快速相关攻击复杂度。
11. 区分攻击：analyzer/distinguisher.py 画线性区分器"优势 vs 数据量"曲线。

--------------------------------------------------------------------
阶段 4：安全性质
--------------------------------------------------------------------
12. 前向/后向安全：analyzer/security.py 判定状态更新是否双射（双射→后向不安全），
    报告状态单向性/熵损失/重同步分析。
13. 可证明安全：判断构造类型（PRF/数论/格/启发式），给 Tier1 归约或 Tier2 严格安全论证
    脚手架；证明本身由"人 + agent"协作完成，不伪造归约。
14. 后量子：Grover 表（128→64、256→128 位等效），判定是否含 Shor 型可攻击结构。

--------------------------------------------------------------------
阶段 5：性能与对比
--------------------------------------------------------------------
15. FPGA 估算：analyzer/performance.py 定频模型（LUT/寄存器/关键路径/吞吐）。
16. 软件基准（可选）：把算法翻译成 C，在 WSL 下 -O3 测 MB/s 与 cycles/byte（询问用户是否要做）。
17. 对比表：analyzer/comparison.py 与 10 个参考密码（ChaCha20/Trivium/Grain-128/ZUC/Salsa20/RC4/A5-1 等）对比。

--------------------------------------------------------------------
阶段 6：报告
--------------------------------------------------------------------
18. 生成报告骨架：python cli.py report <适配器>:<类名> --rule <规则> --cells <n> --key-bits <k>
    （产生 results/report.md + 全部图/表）
19. 人工补全：算法规范（形式化 F:(K,IV)→keystream）、安全论证、结论与未决问题，
    形成完整可投稿报告（英文）。

【最终交付】
1. results/report.md（或转 LaTeX）完整报告 + 全部图表；
2. 一份中文「分析结论摘要」：算法结构要点、各测试结论、最佳已知攻击、安全余量、
   诚实标注的未决问题。
